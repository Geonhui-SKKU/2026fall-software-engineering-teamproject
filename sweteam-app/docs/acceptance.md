# Prototype acceptance evidence · SRS v1.01

Source: [Appendix B.6, pp. 49–51](../../srs_team2.pdf#page=49). **Demonstrated** means the named behavior is shown with synthetic fixtures; **partial** means important criteria are still missing; **deferred** means the case cannot be exercised meaningfully in this prototype. These are not production acceptance results.

External integrations, verified rule coverage, localization, and production performance, security, and accessibility certification remain outside this submission.

## Submission verification

- Clean staging install from the lockfile, lint, seven unit tests, and production build passed.
- The built app passed a Chromium walkthrough covering reminder and Applied persistence, timetable conflict placement, pointer drag and the semester selector, downstream withdrawal effects, plan isolation, the 87/99/96 regression, report download, demo reset, and route reloads.
- At a 390px Chromium viewport, feature navigation and visible keyboard focus worked; the timetable and roadmap scroll inside their own panels. This is a smoke check, not a WCAG audit or cross-browser certification.
- The archived SKKU notice linked as a historical reference returned HTTP 503 during verification. The synthetic notice workflow does not depend on that page.
